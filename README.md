# Value Study Studio

An art warm-up about seeing lightness through hue. Choose the darkest, middle and lightest of three named colors. The studio computes relative luminance locally, identifies the first reversed pair, and shows the measured order. A Firebase AI Logic coach can turn that specific comparison into a painting exercise. The default request is device-only. Choosing hybrid explicitly allows cloud fallback. The displayed inference source comes from the SDK response.

Use Node **24.12 or later**, matching the pinned Firebase SDK's engine requirement. Run `npm ci`, `npm test`, then `npm run dev` or `npm run build`. The four original palettes and scoring work without a Firebase account. Choose Lantern, Plum, Canopy for a deliberate error in the first study. Try again with Plum, Canopy, Lantern.

For an isolated judging environment, enable Firebase AI Logic with the Gemini Developer API, register a web app and configure Firebase App Check with reCAPTCHA Enterprise for its judging domain. Supply the site's public web configuration in the untracked file `public/judge-config.json` with keys `firebaseConfig` (the web app configuration object) and `appCheckSiteKey` (the public Enterprise site key). Keep all service credentials and production configuration out of source and submission materials. Serve the production build over HTTPS. Use a supported Chrome installation with the on-device model ready. Record one successful device-only exercise and one cloud exercise with their SDK-reported routes before claiming either ran. On failure the app reports the failure and retains the learner's measured result.

[Firebase hybrid web setup](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started) · [Inference source and modes](https://firebase.google.com/docs/ai-logic/hybrid/web/configuration-options) · [Competition rules](https://firebasehybridaihackathon.devpost.com/rules)

Copy `judge-config.example.json` to `public/judge-config.json` and fill it from an **existing authorized isolated** Firebase web app. `npm run check:config` checks public configuration shape; it does not contact Firebase or prove inference. The example intentionally fails validation until filled. No service account, Gemini server API credential or App Check debug token belongs in that public file.

After finishing a palette, select a mode and click **Prepare AI coach**. Preparation loads the Firebase service before the separate **Get a painting exercise** click starts device initialization. This preserves the device initialization's user interaction. Hybrid now initializes the device model too and leaves cloud fallback to the SDK. Strict requests reject a mismatched or unreported source. The **Judging evidence** panel exports actual request outcomes with the requested mode, SDK source, response, timestamps, environment and source fingerprint. An export is a browser observation requiring review, not a signed provider attestation or automatic runtime classification.

See [JUDGING.md](./JUDGING.md) for the exact configuration, local development and recording sequence. To execute the existing CAGE planner, event store and learning process against this build, use `python3 scripts/cage_judging_run.py --cage-root /path/to/cage-agi-orchestrator --out /private/path/to/evidence`. The CAGE checkout must be authorized and current. This runner makes no model calls, deployment, account changes or submissions. SDK doubles in unit tests are explicitly synthetic.
